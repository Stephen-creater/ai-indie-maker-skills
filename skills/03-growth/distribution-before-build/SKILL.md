# Distribution Before Build

Use this skill when the user wants to avoid overbuilding before demand is proven.

## Core Principle

Build is one step. First prove that a reachable group cares enough to click, reply, join a waitlist, request access, or pay.

## Validation Routes

Choose based on product type:

- **Landing + waitlist**: best when there is a clear offer and a future launch.
- **Comment/reply test**: best when pain appears under YouTube, Reddit, TikTok, X, or forum discussions.
- **Demo video**: best for visual products, mobile apps, AI tools, creator workflows.
- **Manual concierge**: best when workflow is valuable but automation is not built.
- **Open-source teaser**: best for developer tools and utility products.
- **Directory/listing test**: best for AI tools, SaaS alternatives, templates, plugins.

## Process

1. Define the exact user and pain.
2. Write the one-sentence offer.
3. Pick 3 channels where the user already appears.
4. Create the smallest artifact: landing, Loom/TikTok-style demo, GitHub README, waitlist, or screenshot.
5. Post/comment/message without overclaiming.
6. Track replies, signups, clicks, and objections.
7. Decide: build, narrow, reposition, or kill.

## Kill Criteria

- No replies after credible channel attempts.
- People like the concept but no one wants access.
- The only channel is paid ads and budget is unavailable.
- AI/API cost makes trial impossible.
- The user cannot describe a real trigger moment.
