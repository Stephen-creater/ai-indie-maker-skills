# Skill Map

这组 skills 按真实项目推进顺序设计。

## 1. 想法阶段

先用 `indie-saas-idea-classifier` 判断想法属于哪类 SaaS，再用 `niche-saas-opportunity-miner` 深挖人群、痛点、竞品和 MVP。

适合的问题：

- “这个 idea 值不值得做？”
- “我在 Notion / Gmail / 视频生成 / 录屏工具生态里发现一个痛点，怎么判断是不是 niche SaaS？”
- “这个产品更像广告工具站、订阅 SaaS，还是数字产品平台？”

## 2. Build 准备

用 `ai-native-saas-stack-planner` 确定最小技术栈，再用 `harness-docs-builder` 生成 AGENTS.md、PRD、Design.md、Architecture/ARD 和功能规格。

适合的问题：

- “我不会写代码，要用 AI 做这个海外工具，技术栈怎么定？”
- “帮我给这个项目写一套 agent 能长期读的文档。”
- “我想让 Codex/Claude Code 不跑偏，应该先准备哪些文档？”

## 3. 页面与体验

用 `landing-design-md-builder` 把参考网站、目标用户和产品定位转成 Design.md 与 landing page 结构。

适合的问题：

- “帮我从这个参考站提炼设计规范。”
- “这个 landing page 的 hero、CTA、bento 区块怎么安排？”
- “开发者工具产品应该怎么避免 AI 味 UI？”

## 4. 先分发再开发

用 `distribution-before-build` 在正式 build 前验证需求；上线后用 `indie-growth-channel-planner` 规划持续增长渠道。

适合的问题：

- “我还没做完产品，怎么先验证需求？”
- “我的产品适合 Reddit、YouTube、TikTok、GitHub 还是 SEO？”
- “我想做 AppSumo lifetime deal 冷启动，怎么设计？”

## 5. 成本、上线、合伙

用 `ai-saas-unit-economics-launch-qa` 估算 AI 成本和上线风险；用 `solo-founder-collaboration-guardrails` 判断合伙分工。

适合的问题：

- “这个 AI 图片/视频工具能不能给免费试用？”
- “上线前支付、积分、登录、监控怎么检查？”
- “朋友负责推广我负责开发，五五分合理吗？”
