# Source Distillation

这份蒸馏来自一场关于“独立开发者出海、AI coding 和海外工具增长”的分享。原始录音文字稿和 PPT 截图位于 `source/`，以下是面向使用的结构化压缩。

## 90% 精华

1. 独立开发者不是只写代码，而是在同时承担产品、设计、工程、增长、客服、支付、上线兜底。
2. 速度优先：选 AI 生成能力最稳定的技术栈，尽快做出可用版本。
3. Build 只是小环节，Distribution 是关键；最好先验证需求，再投入完整开发。
4. 选品有四个高频桶：轻量工具站、中型 API 聚合、垂直 niche SaaS、数字产品电商平台。
5. 不必执着于没人做过的 idea；找已验证需求但体验差、UI 差、垂直场景没做透的机会更现实。
6. AI SaaS 不像传统 SaaS 那样天然有完美规模效应，图片和视频生成类产品尤其要计算边际成本。
7. AI 套壳的价值来自壳：行业上下文、工作流、画布模式、用户体验和特定人群 know-how。
8. AI coding 的核心是 harness：让 agent 先读对文档，再写代码。
9. 需求变化时先改 PRD/功能文档，再让 AI 基于新文档改代码。
10. 设计要沉淀为 Design.md：typography、spacing、grid、colors、radius、CTA、hero、组件规律。
11. 后端/业务流要先口述清楚；自己讲不清楚，AI 很难稳定做对。
12. 推荐流程是 plan -> review -> execute -> test -> fix 循环，而不是一句话让 AI “全部做完”。
13. 上线前要重点检查支付、积分/额度、登录、数据库、错误提示、监控、成本和客服兜底。
14. 增长渠道要按产品类型选：SEO、Reddit、YouTube SEO、TikTok、小红书、GitHub、V2EX、BetaList、AlternativeTo、There Is An AI For That、AppSumo、Trustpilot、Product Hunt、博客外链等。
15. 合伙要谨慎，尤其是第一次合作和五五分；先用短项目验证投入、资源和协作公平性。

## PPT 给出的结构

- 总论：AI 时代 solo 开发的优势与现状。
- 选品：四大 SaaS 选品体系。
- 商业模型：AI SaaS 与传统 SaaS 的边际成本差异。
- 工作流：harness 文档、Design.md、PRD、ARD、superpowers、TDD/spec。
- 增长：SEO、红人广告、社交平台、开发者目录、lifetime deal、review 平台。

## 转写噪声

部分工具名来自语音转写，公开仓库中不把它们当作已核验事实。例如 `strap` 归一为 Stripe，`superbase` 归一为 Supabase，`visa` 归一为 Vercel，`SAST` 在简历语境下更可能是 ATS。其他不确定名称只作为启发，不作为权威引用。
